Auroraflow · Design Audit

Small moves, real polish.
Journal, Team & Services.

A design pass over auroraflow.com focused on high-leverage, on-brand refinements — no redesigns, no new pages, no brand changes. Every proposal below is shown as a Before → After so you can approve them one at a time.

Philosophy

Small but powerful

Each change is a targeted CSS or tiny-JS move. No rebuilds — the existing cream/rainbow/Poiret system stays exactly as it is.

Nothing off-brand

New colour comes only from the existing palette and rainbow signature. Motion matches the site's calm 9.5s "breath" and honours reduced-motion.

One system, reused

A single tinted-chip family, one soft filter transition, and one scroll-reveal utility do the work across all three pages.

One scroll-reveal utility

Small JS

A tiny IntersectionObserver adds a staggered 12px rise + fade as sections enter (journal grid, services grid). prefers-reduced-motion: reduce turns it off completely — matching the rest of the site's motion policy.

Section 05

Technical & performance — all three pages

Not mockable as Before/Afters, but the highest-leverage fixes in this audit. All sizes below were verified against the repo. This extends the home-page performance pass (−89% image weight there) to these page groups.

P1

Convert oversized images to WebP at rendered size

Assets

These pages serve multi-megabyte PNGs into cards rendered at a few hundred pixels — several were exported through a PDF at some point (the *.jpeg.pdf-*.png files) and never optimized. Every one of these is heavier than anything the home page had before its cleanup. Converting to WebP at rendered size is the single biggest performance lever across all three pages.

assets/img — worst offenders
3.7 MB  IMG_3985-Carissa-Bovee.jpeg.pdf-2-.png (bio page)
3.2 MB  IMG_3498-Carissa-Bovee.jpeg.pdf-1500-x-1500-px-.png (bio page)
2.9 MB  Auroraflow.-Acne-Facial-Blog-Post.png (services grid)
2.7 MB  IMG_1165-Carissa-Bovee.jpeg.pdf-1500-x-1500-px-1-.png (team grid)
2.4 MB  Referral-Program-Website.png (journal grid)

Target: tens of KB each at rendered size. Originals kept; og:image stays JPEG/PNG for crawler compatibility — same process already applied to the home page.

P2

Adopt the fluid spacing tokens

CSS-only

shared.css already defines --space-section-y and --space-page-x, but all three pages hardcode section padding — journal 60px 40px 80px, team 64px 40px 100px, services 48px 40px 100px. Pointing these at the tokens unifies vertical rhythm sitewide and tightens correctly on phones, with zero desktop cost.

✓

Same fix already shipped on the home page's .about and .testimonials sections. Mechanical change, easy to review per-page.

P3

Re-export clean headshots

Content
!

The CSS crop hides it (every team photo displays at a uniform 3:4), but sources range from 400px to 1600px and several went through a PDF export. Re-exporting consistent, appropriately sized headshots fixes both the quality floor and most of P1's team-page weight in one batch.

P4

Journal post consistency check

Content
!

The ~10 posts under journal/ were hand-authored independently over time. When implementing J1–J5, verify each post's heading hierarchy and byline treatment page-by-page so the index changes and the posts stay one system.
